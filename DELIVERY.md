# DELIVERY — Le Musée endormi · The Sleeping Museum

Delivery note for v1.0.0 (2026-10-31), written honestly per workshop rules:
what was really tested, tuned, and what remains unverified.

## What is delivered

- Complete game, single self-contained `index.html` (engine + solver + i18n
  EN/FR/ES with EN default + Canvas rendering + synthesized WebAudio audio +
  localStorage progress). No dependencies, no network calls.
- 8 levels, progressive: L1 one patroller · L2 vision blocked by display
  cases · L3 rotating sentry + patroller · L4 decoy (unsolvable without it)
  · L5 two patrols + case island · L6 aisles + sentry + patrol · L7 three
  patrols in step · L8 finale (4 guards, 4 gems).
- Medal per level for finishing at or under the target (par), par = true
  optimum computed by the built-in BFS solver: [12, 14, 16, 12, 24, 27, 30, 38].
- Controls: arrows/WASD/ZQSD, Space (wait), L/X (decoy), U (undo), R
  (restart), on-screen D-pad + buttons for touch. Capture → immediate level
  restart (per spec). Undo is unlimited within a level attempt.

## Real verification performed

Node tests (23 assertions, `games/musee-endormi-dev/tests.mjs`, run against
this exact `index.html` via vm):
- all 8 levels solvable; embedded PARS equal solver optima; optimal paths
  replay to a win;
- L4 unsolvable without the decoy (teaching guarantee);
- no player start watched / on a guard; no gem on the exit;
- ray occlusion: walls and vitrines stop lantern rays (exact cell lists);
  a player behind a vitrine is not spotted;
- determinism: identical action sequences produce strictly identical states;
  patrol wrap and sentry facing cycle verified step by step;
- capture rules: watched-at-end-of-turn, player-onto-guard, guard-onto-player,
  win checked before guard phase, illegal moves consume no turn;
- decoy semantics: one use, nearest guard, frozen for the two following
  turns (no move, no vision), contact with a frozen guard still fatal;
- exit locked until all gems; i18n key parity EN/FR/ES; cloneState
  independence; 40 000-action fuzz (invariants: moves == successful actions,
  alive player never watched after resolution, no exceptions).

Real browser play (local HTTP + in-app browser):
- Home → Play → **L1 won by real keyboard events** (12 moves, medal, best
  saved, L2 unlocked);
- **capture on L2** (walked into the watched row) → “Spotted!” overlay →
  **automatic restart** (state fully reset);
- **L4 won with the decoy** (throw → 2 free moves through the always-watched
  corridor; distract counter 2→1→0 observed);
- **L2 won** (14 moves);
- i18n switched to FR live (HUD, plaque, buttons) and back through ES to EN;
- touch D-pad (pointerdown), Wait, Undo (restores position and move count),
  Restart buttons all functional; decoy button greys when spent;
- mobile layout at 390×760: no overlap (HUD/canvas/plaque/controls), D-pad
  visible, canvas fits;
- canvas pixel probes: lit cells clearly brighter than floor (+40 luminance),
  walls darker than floor with blue top edge, gem amber / guard red / player
  teal all distinct.

## Honest limitations

- The in-app browser pane used for testing loses real-input routing and
  freezes rAF when unfocused (known local-tool issue). Gameplay was driven
  with synthetic DOM events through the game's own handlers, and rendering
  was verified by pixel probes rather than eyeballing. The open-exit green
  glow specifically could not be pixel-verified because the canvas had
  stopped repainting at that moment; the code path is shared with the locked
  exit which was verified. Evidence screenshots in `evidence/musee-endormi/`
  were saved for human review, not machine-inspected.
- No playtesting on a physical phone; no audio mixing review by ear.
- Medal rule is a single medal at exact par (per specification). A Kimi K3.1
  Pro review suggested tiered medals (bronze/silver/gold); not adopted — the
  spec asks for one optional medal — but its L4 hint rewrite and an
  input-restart debounce (held keys after restart) were adopted.
